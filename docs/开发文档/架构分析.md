# S9 桌宠伴侣 · pet_companion

> **一台会说话、会看、会动手的桌面机器人。**
> ESP32-S31 负责"身体"（感知 / 表达 / 执行），云端大脑负责"智力"（听 / 想 / 说 / 记）。
> 两端用**一条 WebSocket 长连接 + 一套能力自述协议**接起来 —— 设备在 NAT 后面也能被云端精确指挥。

```
┌─ 云端大脑（智力） ───────────────────────────────────────────┐
│ ASR(SenseVoiceSmall) → LLM(deepseek-flash) → TTS(qwen-audio) │
│ 工具调用回灌（function calling，真实结论回流到模型）         │
│ AstrBot v4.29.1 插件化编排（工具注册/记忆/生图/音乐/关怀）   │
│ pet-gateway :8081  唯一入口 / 能力中继 / 媒体归一化          │
└──────────────────────────────────────────────────────────────┘
                      ⇅  一条 WebSocket 长连接（设备永远主动外连，云端借此穿透 NAT）
┌─ 边缘端（身体 · 本仓库） ────────────────────────────────────┐
│ 语音上行 · 工具执行 · 端侧视觉 · 双通道音频 · 800×480 UI     │
│ ESP32-S31 RISC-V @240MHz · 16MB Flash + 8MB PSRAM            │
└──────────────────────────────────────────────────────────────┘
```

## 1. 这台设备能做什么

| 能力 | 用户视角 | 端云分工 |
|---|---|---|
| 🗣 **语音对话** | 按键说话 → 屏幕出字 + 喇叭出声，可随时打断 | 端：录音/VAD/上行；云：ASR + LLM + TTS |
| 🧰 **16 个工具** | "打个卡""拍张照""放首晴天""灯调暖一点" | 端：执行；云：判断该调哪个工具 |
| 👁 **看图讲解** | "看看我手上这是什么" → 拍照上传 → 语音回答 | 端：拍照上传；云：视觉大模型 |
| 🧑‍💼 **人脸打卡** | 走到设备前说"打卡"，认出是谁后盖章 | **端侧推理**（不联网也认人）+ 云：报结论 |
| 😊 **表情包** | 聊天中突然收到一张表情图，浮窗显示 | 云：检索/生图；端：解码上屏 |
| 🎵 **点歌** | 云端搜歌 → 喇叭放 → 同时存进 SD 卡曲库 | 云：音源代理；端：播放 + 落盘 + 歌词 |
| 🖼 **动态壁纸** | 本地壁纸池定时轮换，断电记忆 | 纯端侧 |
| 🪟 **本地功能** | 文件管理 / 录像 / 录音 / 蓝牙音箱 / 网页管理端 | 纯端侧，离线可用 |

**关键取舍**：设备端**零大模型**（连 ASR 都不跑），只有两个小型端侧模型做人脸检测/识别 ——
那是**隐私 + 时延 + 离线可用性**三者共同决定的例外，不是省事。

## 3. 系统分层总览

整套系统在**纵向（端↔云）**分五层，在**横向（设备内部）**分四层。这两条切分线是理解本工程的全部：

```
┌─ 纵向：端 ↔ 云（第 6 节详述） ──────────────────────────────────────────────────┐
│ L5 应用编排  │ 设备：会话状态机 / 云端：AstrBot 插件体系                        │
│ L4 能力协商  │ 设备 caps 上行（我会什么）  ⟷  云端 tools 注册（该调什么）       │
│ L3 指令通道  │ 云端 action 下行 / 设备 action_result 回执（双向同步调用）       │
│ L2 内容通道  │ text / emotion / audio(URL) / image(URL) 下行；HTTP 拉取大对象   │
│ L1 传输      │ 单条 WebSocket 长连接 + 指数退避重连 + JSON 帧                   │
└─────────────────────────────────────────────────────────────────────────────────┘

┌─ 横向：设备内部四层 ────────────────────────────────────────────────────────────┐
│ ui/          LVGL 页面 · 桌宠浮窗 · bin 字体（只能通过队列/回调找中间层）       │
│ app/         main.c：纯初始化编排，写业务逻辑属违规                             │
│ middleware/  硬件业务：ai / camera / audio / media / net / periph / face_db     │
│ components/  vendor 组件：esp_xiaozhi(MCP+音频管线) · esp_littlefs · 蓝牙 · 手势│
└─────────────────────────────────────────────────────────────────────────────────┘
```

**两条铁律**（`docs/工程规范/01_工程分层架构.md`）：

1. `middleware/` **不许** `#include "lvgl.h"` —— 中间层不认识 UI；
2. `ui/` **不许**直接 `xTaskCreate` 硬件任务、不许直接操作 I2S/I2C 寄存器。

## 4. 边缘端分层（设备内部）

设备端 `main/middleware/ai/` 是整条端云链路的落点，自身又分五级，**任何一次功能改动都能定位到其中一级**：

```
┌ ① 传输层 ──────────────────────────────────────────────────────────────┐
│ ws_client.c   唯一长连接。supervisor 任务守护，1s→30s 指数退避重连。   │
│               收包按 JSON 对象括号配对切帧（不依赖 '\n' 或 fin）。     │
├ ② 解码层 ──────────────────────────────────────────────────────────────┤
│ event_bus.c   把下行 JSON 拆成 7 种帧：text/emotion/audio/image/       │
│               action/system/error。收包任务里只入队不阻塞。            │
├ ③ 执行层 ──────────────────────────────────────────────────────────────┤
│ ai_action.c   动作队列 worker（栈 7168B）：参数模板合并 → MCP 引擎     │
│               tools/call 或本地直调 → 回 action_result。               │
│ ai_punch / ai_camera / ai_music / ai_speaker / ai_light / ai_device    │
│               六个业务模块，共注册 15 个 MCP 工具。                    │
├ ④ 会话层 ──────────────────────────────────────────────────────────────┤
│ xiaozhi_service.c  会话状态机 + codec 独占租借 + 双播放通道            │
│               TTS(pri=2 抢占) / 音乐(pri=1 让位)，靠 audio policy      │
│               做"暂停-续播"，TTS 结束后音乐自动接回。                  │
├ ⑤ 表达层 ──────────────────────────────────────────────────────────────┤
│ ui/  pet_overlay 桌宠浮窗 · tab_camera/video/files/music/rec/sys       │
│      overlay_manager 浮层调度 · ui_binfont 全 CJK bin 字体             │
└────────────────────────────────────────────────────────────────────────┘
```

**端侧智能（Local Intelligence）** —— 全部在 `middleware/camera/`：

| 能力 | 模型 | 体量 | 推理耗时 | 为什么必须在端 |
|---|---|---|---|---|
| 人脸检测 | `espdet_pico_224_face` | ~300 KB | <100 ms | 取景框实时画框，上传云端不可能 |
| 人脸识别 | MFN(MobileFaceNet) + MSR + MNP | 1.30 MB + 60 KB + 127 KB | **324 ms/次** | 人脸特征不出设备 = 隐私；断网也能打卡 |
| 手势识别 | hand_detect + hand_gesture | ~200 KB | 实时 | 同上 |

人脸库（`face_db`）= SD 卡上的二进制库，双世代号 + CRC 校验，掉电不丢。

## 5. 云端大脑分层

云端**不是"一个模型"，而是四层能力栈**（全部实测在线：`/health` → `version 0.8.1`）：

```
┌─ L4 内容层 ────────────────────────────────────────────────────────────┐
│ 音乐音源代理 music_proxy :8080   自建网易云 API + 2 个兜底源           │
│   契约 GET /v1/search · /v1/url · /v1/lyric · /v1/pic · /v1/download   │
│ 文件/网盘 alist :5244 —— 表情包、素材的检索后端                        │
├ L3 智力层（外部 API，云端只做路由与降级） ─────────────────────────────┤
│  LLM      deepseek-flash            对话 / 工具决策 / 人格             │
│  ASR      SenseVoiceSmall           OpenAI 兼容 /audio/transcriptions  │
│  TTS      qwen-audio-3.1-tts-flash  少女音，WAV 24 kHz                 │
│  VL       多模态消息段              image 段进 LLM = 看图              │
│  Embed    openai_embedding          长期记忆 / 表情包语义检索          │
├ L2 编排层 ─────────────────────────────────────────────────────────────┤
│ AstrBot v4.29.1（容器 :6185，Open API /api/v1/chat SSE）               │
│   插件体系：pet_device(工具注册) · livingmemory(记忆) · omnidraw(生图) │
│   · music · proactive_chat(主动关怀) · self_learning · parser …        │
├ L1 接入层 ─────────────────────────────────────────────────────────────┤
│ pet-gateway（FastAPI :8081，systemd 常驻，MemoryMax=256M）             │
│   /ws/{sid} 设备长连接 · /action 工具中继 · /caps 能力查询             │
│   /media/{name} 媒体出口 · /upload/{sid} 图片入口 · /push 主动推送     │
│   /health 健康检查                                                     │
└────────────────────────────────────────────────────────────────────────┘
```

**为什么必须有网关这一层**（而不是设备直连 AstrBot）：

1. **协议收敛**：设备只说一种 JSON 方言，AstrBot 的 SSE / 附件 / provider 细节全在网关里消化；
2. **媒体归一化**：云端下发的图常是 GIF/PNG 或渐进式 JPEG，设备解码器只吃 baseline JPEG —— 网关 `normalize_image()` 负责转码，**设备端零改动**；
3. **NAT 穿透**：设备在路由器后面，云端的插件打不到它。只有**设备主动建立的那条 WS** 是唯一稳定反向通道，网关就是这条通道的持有者；
4. **降级兜底**：TTS 挂了只掉语音不掉文字；AstrBot 重启时网关重试一次；模型回复超长时 `tts_shorten()` 截断到 200 字，**文字仍是全文**。

## 6. 端云契约：五层接入模型

设备端与网关之间只有 **11 种帧**（上行 5 类 + 下行 7 类，`text` 双向共用），全部单行 JSON。这张表就是"边缘接入云端大脑"的完整协议：

### 6.1 上行（设备 → 云端）

| 帧 | 触发 | 作用 |
|---|---|---|
| `{"type":"caps","model":"ESP32-S31-Korvo-1","tools":[…]}` | 连上 / 重连 | **能力自述**：我会干什么（第 9 节） |
| `{"type":"pcm","data":"<b64>","sample_rate":16000}` | 按键说完一句 | 语音上行（16k/mono/s16 裸 PCM） |
| `{"type":"text","text":"…"}` | 屏幕键盘 | 文字回合 |
| `{"type":"event","event":"action_result","id":N,"ok":1,"data":"…"}` | 动作执行完 | **回执**：让云端的同步调用拿到真实结论 |
| `{"type":"event","event":"barge_in"}` | 用户打断 | 停播 + 取消排队 |
| `{"type":"image_req","attachment_id":"…","text":"这是什么"}` | 拍完照要讲解 | 触发视觉问答 |
| `POST /upload/{sid}` (HTTP) | 拍照后 | 把原图字节送到云端（≤4 MB） |

### 6.2 下行（云端 → 设备）

| 帧 | 作用 | 设备端落点 |
|---|---|---|
| `{"type":"text","text":"…","role":1}` | 回复文本（role=0 是 ASR 回显） | `event_bus` → 气泡 |
| `{"type":"emotion","name":"speaking"}` | 表情/嘴型（thinking/speaking/idle/…） | `pet_overlay` |
| `{"type":"audio","url":"/static/tts_xxx.wav"}` | TTS 音频 URL | `xiaozhi_service`（pri=2 通道） |
| `{"type":"image","url":"/media/xxx__n.jpg"}` | 表情包 / 配图 | `cloud_media_service` 下载→解码→浮窗 |
| `{"type":"action","id":N,"name":"punch","args":{}}` | **云端指挥设备做事** | `ai_action_dispatch()` |
| `{"type":"system","cmd":"capture\|punch\|light\|set_volume\|reboot\|explain"}` | 系统级指令 | `event_bus::handle_system()` |
| `{"type":"error","code":"…"}` | 失败可见 | 气泡 + 日志 |

> **相对 URL 的处理**：云端只发 `/static/…` 相对路径，设备用 `ws_client_get_http_base()`
> 把 `ws://host:port` 换成 `http://host:port` 再拼 —— 换服务器地址只改一处。

## 7. 一次完整回合的时序

**语音点歌（走 LLM 工具调用 → 反向 relay）：**

```
用户按键说"放首晴天"
  │
  ├─ 设备  voice_service：PTT 录音 → PCM 16k → base64 → ws_client
  │                                                        └─▶ 网关 /ws
  │                                                              │
  │                                              ① 立即下行 emotion:thinking
  │                                                              │   （ASR+LLM 要 9~18s，不能静默）
  │                                              ② PCM 封 WAV → SenseVoice → 文本
  │                                              ③ 回显 text(role=0)：「放首晴天」
  │                                              ④ 文本 → AstrBot /api/v1/chat (SSE)
  │                                                              │
  │                                                      LLM(deepseek-flash)
  │                                                     决定调用 pet_music
  │                                                              │
  │                                              ⑤ 插件 POST 网关 /action
  │  ◀── {"type":"action","id":7,"name":"music","args":{"name":"晴天","__text":"放首晴天"}}
  │  │
  │  ├─ 设备  ai_action：查动作表 → do_music()
  │  │        ① 本地曲库命中？→ 直接本地播放（离线可用）
  │  │        ② 未命中 → GET music_proxy /v1/search → /v1/url → 起播
  │  │        ③ 成功 → 异步落盘 /sdcard/music/<歌手>-<歌名>.mp3 + .lrc
  │  │
  │  └──▶ {"type":"event","event":"action_result","id":7,"ok":1,"data":"晴天"}
  │                                                              │
  │                                              ⑥ 拿到真实结论才回话
  │                                              ⑦ 只回文字、不出 TTS（否则顶掉音乐）
  ▼
喇叭出声 + 屏幕显示歌名 + SD 卡多一首歌
```

同一套通道反方向也成立：**云端插件可以主动推**（`POST /push`，"该休息了"），
这是桌宠"会先开口"的基础。

## 8. 双入口调度：为什么既有快速路又有大模型

网关收到文本后，是**先试确定性匹配，不命中才交 LLM**：

```
设备文本 ──▶ match_intent()
                ├─ 命中设备自述的 aliases（"打卡""放首晴天"）
                │     └─▶ 直接下发 action，不进 LLM、不花 token
                │         延迟 = 一次动作 RTT（< 1 轮 TTS）
                └─ 不命中
                      └─▶ AstrBot LLM → 可能自己决定调用 pet_* 工具
                           （同一批动作，走 function calling）
```

| 维度 | 关键词快速路 | LLM 工具调用 |
|---|---|---|
| 覆盖 | 只有确定性短语（宁可漏，不误触发） | 任意自然语言 |
| 成本 | 0 token | 每轮带上工具说明书 |
| 延迟 | 一次 RTT | LLM 推理时间 |
| 危险动作 | 打卡/拍照只走这条路（**不让模型幻觉"成功了"**） | — |

**为什么打卡不让 LLM 决定**：模型在工具失败时会"编一句成功"，用户以为打了卡、实际没打。
⇒ 确定性意图走高确定性通道，结论由设备回执决定。

## 9. 能力自述协议 caps

**"设备会干什么"的唯一真相在固件里，不在云端。**

```
设备启动
  └─ ai_action_report_caps()
       ├─ 遍历 MCP 引擎 tools/list（15 个工具的真实 schema）
       ├─ 用 ai_action.c 的 TOOLS[] 覆盖文案（desc / label / aliases / arg_key）
       ├─ 补一个引擎里没有的纯本地动作（wallpaper）
       └─ 拼成 12 KB JSON → {"type":"caps", ...} 上行

云端网关
  └─ 存进 SESSIONS[sid].caps；GET /caps 供插件查询

AstrBot 插件 astrbot_plugin_pet_device
  └─ 每 45s GET /caps → 动态注册成 pet_<name> 的 LLM 工具
```

**收益**：加一个设备动作，**只改固件** —— 网关和插件一行都不用动。
旧固件不上报 caps 时，插件回落到内置 `_DEFAULT_TOOLS`，不会失能。

## 10. 媒体链路的端云协同

两条链路的难点都不在"传"，而在**两端能力边界不一致**：

**图片下行（表情包）**

```
云插件产出 GIF(500×500) / PNG(1024×1024)
   └─▶ 网关 normalize_image()
          ├─ 合规（baseline JPEG ≤1M 像素 ≤1150KB）→ 原名直发
          └─ 不合规 → Pillow 转 RGB → 等比缩 → baseline JPEG(q85) → <stem>__n.jpg
   └─▶ {"type":"image","url":"/media/xxx__n.jpg"}
          └─▶ 设备 cloud_media_service：下载 → 硬件 JPEG 解码 → 浮窗
                 ├─ 上限：≤1M 像素 / ≤1200KB / 只支持 baseline-DCT
                 └─ 落盘 /sdcard/cloud_media，只保留最近 32 张
```

**音频下行（TTS 与音乐共存）**

```
网关 TTS ──▶ {"type":"audio"} ──▶ 设备 pri=2 通道（TTS）
用户点歌 ──▶ 本地/云音源 ──────▶ 设备 pri=1 通道（音乐）

TTS 起播时 audio policy 自动暂停音乐通道（保留播放位置）
TTS 结束 → 自动续播音乐 —— 用户听不到"被切断"
```

## 12. 构建、烧录、部署

**设备端**（ESP-IDF v6.1，Windows 双击仓库根目录 `IDF_v6.1_Powershell.lnk` 打开终端）：

```powershell
idf.py reconfigure
idf.py build
idf.py -p COM9 flash        # 全量烧录；分区偏移变更时必须整片烧（含 storage.bin）
```

- 网关地址可在网页管理端改（存 NVS `pet_cfg/ws_base`），也可编译期注入 `PET_GATEWAY_URL_DEFAULT`
- 模型/字体走 littlefs（`littlefs_content/`），**不进固件**，改素材只重烧 storage

**云端**（参考部署 120.76.230.17）：

```bash
# 网关：FastAPI + systemd
scp tools/diag/ws_gateway.py root@<server>:/opt/pet_gateway/
ssh root@<server> systemctl restart pet-gateway
curl -s http://127.0.0.1:8081/health          # {"ok":true,...,"version":"0.8.1"}

# 音源代理：Docker
cd tools/music_proxy && docker compose up -d music-proxy
```

配置见 `tools/diag/config.json`（端口 / AstrBot 地址 / 密钥占位；**真实密钥只存服务器，chmod 600**）。
网关会自动读取 AstrBot 的 provider 配置 —— **换 TTS 音色 / 换 ASR 模型只要在面板改，设备端零感知**。

## 14. 工程约束（踩过的坑）

这些不是建议，是**违反就炸**的：

| 约束 | 原因 |
|---|---|
| **内部 RAM 只剩 ~4 KB 余量** | WiFi DMA 独占 51 KB 挪不走；任务栈 + RTOS 对象刚性占内部 RAM |
| 碰 NVS / littlefs / flash 的任务栈**必须内部 RAM** | IDF v6.1 每次擦写前断言 SP 在内部 DRAM，无 API 豁免 |
| `malloc()` 在本工程**优先给 PSRAM** | `SPIRAM_MALLOC_ALWAYSINTERNAL=0`；但 `xTaskCreate`/`xQueueCreate` 一律只从内部拿 |
| 判内存只看 `largest_free_block`，不看 `free_size` | TLSF 不解决碎片，"总空闲够"不等于"能分配" |
| **WS 收包任务里禁止任何阻塞 IO** | 阻塞一次就是成片丢包（心跳正常但响应时好时坏） |
| 非 LVGL 线程**不得**碰 LVGL | 回调只置 `volatile` 标志，由 LVGL 定时器刷新 |
| `lv_event_get_user_data(e)` ≠ `lv_obj_get_user_data(obj)` | 两个存储，混用会静默失效（行为不对但日志全对） |
| 云端下发的图片**必须**归一化 | 设备 JPEG 解码器只吃 baseline、≤1M 像素 |
| ESP32 上打 64 位值用 `%llu` / `%lld` | `%zu` 只给 `size_t`，用错会 varargs 槽错位（打出垃圾数） |

完整清单见 `docs/工程规范/11_遇到的问题.md`（F1~F72）与 `docs/开发文档/内存管理规划.md`。
