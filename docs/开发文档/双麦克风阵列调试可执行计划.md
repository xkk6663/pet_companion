### 1.3 datasheet **没有**给出的东西（必须写清楚，否则又会误判）

1. **`INPUT1 / INPUT2` 没有引脚映射表**。全文只在 `0x72/0x73` 里出现这两个名字，没有一处说明它们对应 `MIC1P/N` 还是 `MIC2P/N`。
2. **差分档的极性没有写**。`LSE/RSE=0` 只说 "DIFF MODE"，没写是 `P−N` 还是 `N−P`。
3. `es8389_reg.h` 里那些 `ES8390: LIN1-RIN1 / RIN2-LIN2` 注释是**另一颗芯片**的对照，不能当 ES8389 的定义。§28.2 把枚举名 `DIFF_MIC2N2P` 当作「麦 2 自己的一对」的依据，强度应降为「疑似」。
4. `0x73` bit7 虽然叫 `Reversed`，但描述是 **Reserved** ⇒ 不存在「写 bit7 就能翻 R」的捷径（驱动 `es8389_pga_gain_byte()` 的 `reverse` 参数恒传 0）。
5. 官方原理图 PNG 只画 codec 侧耦合电容，**麦克风本体与偏置在另一页** ⇒ 「两只麦都焊了且已供电」仍以实机 RMS 为准。

## 2. 调试所需知识补齐

### 2.1 相关系数到底能证明什么

`diag` 里的 `corr = Σ(l·r) / √(Σl²·Σr²)`，窗口 5 s、只统计块 RMS ≥ 150 的语音段。

| 现象 | 数学含义 | 能不能推「双麦」 |
| --- | --- | --- |
| `corr ≡ +1.000`，`L_rms ≈ R_rms` | `R = L` 逐样本严格副本 | ❌ 单路复制 |
| `corr ≡ −1.000`，`L_rms ≈ R_rms` | `R = −L` 逐样本严格反相副本 | ❌ 单路取负 |
| `corr` 在 −0.4 ~ −0.99 波动、`L_rms ≠ R_rms` | 两路不是严格副本；有独立成分或相位/噪声差 | ⚠ **不能单独证明**：同一差分对经不同 HPF/增益/噪声，或宽带语音高频去相关，也会波动 |
| `\|corr\| < 0.3` 持续 | 远场 / 混响 / 一路是底噪 / L-R 槽映射错 | ❌ 先查接线与槽位 |

★ **关键**：严格副本的相关系数**不受频率、混响、音量影响**，恒为 ±1.000。所以「不是副本」这条结论稳；「因此是两只麦」这条不稳，必须有隔离对照（P4）。

### 2.2 阵列物理（5 cm / 16 kHz）

| 量 | 值 |
| --- | --- |
| 最大到达时延 `τ = d/c` (d=0.05 m, c=343 m/s) | **145.8 μs = 2.33 个采样点 @16 kHz** |
| 相位差 @500 / 1000 / 2000 / 4000 Hz | 26.2° / 52.5° / 105.0° / 209.9° |
| 相位差达 180° 的频率 | ≈ **3.43 kHz** |

⇒ ① 两麦同声源时**低频强相关**，高频因相位差快速去相关，`corr` 随说话内容/距离波动是正常物理现象；② 2.3 个采样点的时延对 GSC 是可分辨的，但对「肉眼比对波形」几乎不可见；③ 不能用「corr 不是 −1」直接判两麦，也不能用「corr 接近 −1」直接判副本。

### 2.3 差分 / 单端与极性

- 差分 `P−N` 与 `N−P` 只差一个负号 ⇒ **硬件反接 = 整路 `corr` 变号**，幅度谱不变。这是 §28 假设的物理基础。
- 单端档只取某一根脚（`MIC1P` / `MIC2P` / `MIC2N` / `MIC1N` 之一）。**「`MIC2N` 单端没信号」不能推出「MIC2P 上没麦」**——这是 §24.1 已经纠正过的错，别再犯。
- 差分档同时取一对脚；若右麦的一对被反着接，软件把 R 取负即可还原（或让 codec 自己做，见 2.5）。

### 2.4 `0x72 / 0x73` 位编码速查

| 字节 | bit6 SE | bit5:4 | gain | 驱动枚举名 | 含义（按驱动注释） |
| --- | --- | --- | --- | --- | --- |
| `0x1A` | 0 DIFF | 01 INPUT1 | 0xA=24.5 dB | `DIFF_MIC1P1N` / `DIFF_MIC2N2P` | **当前正常态**；L=麦1差分，R=驱动注释 `MIC2N−MIC1P`（有歧义） |
| `0x5A` | 1 SE | 01 INPUT1 | 0xA | `SINGLE_MIC1P` / `SINGLE_MIC2N` | L=MIC1P，R=MIC2N（§20.7 历史实验） |
| `0x6A` | 1 SE | 10 INPUT2 | 0xA | `SINGLE_MIC2P` / `SINGLE_MIC1N` | L=MIC2P，R=MIC1N（MIC2P 复测档） |
| `0x7A` | 1 SE | 11 BOTH | 0xA | — | datasheet 有 `BOTH SELECTED`，驱动未定义，语义未知，**不要拿来当正式配置** |

★ `mic_fe_attach_codec()` 日志里的 `sel=N` 是 `(reg>>4)&0x7`（即上表 3-bit 编码），`gain=N` 是 `reg & 0xF`（增益档号，不是 dB）。

### 2.5 ★ 新增：硬件级调试位（本轮最重要的知识补齐）

工程已有 `esp_codec_dev_write_reg(mic, reg, val)` 通道，以下探针**不需要改托管组件**，只需在业务层加开关（P4，待授权）。

| 目的 | 寄存器 / 值 | 预期 | 价值 |
| --- | --- | --- | --- |
| **硬件翻 R 极性** | `0x25` default `0x06` → **`0x26`**（置 bit5 `ADC2_180C`） | `corr` 变号，效果等价于软件 `MIC_FE_INVERT_R`，但**在 codec 内完成**：全链路生效、不占 CPU、无 `-32768` 钳位、MONO 下也真正改变上行 R | 若最终确认右麦反接，这是比逐帧取负更正规的修法 |
| **造「副本对照组」** | `0x23` default `0x00` → **`0x10`**（置 bit4 `ADC2_CF_SRCSEL`，ADC1 → ADC2） | `corr ≡ +1.000` 且 `L_rms ≈ R_rms` | 一次校准 diag 本身 + 证明 L/R 槽映射没搞反；**判读基线必须由它建立** |
| **单路静音** | `0x20` → `0x02`（bit1 mute ADC1）/ `0x01`（bit0 mute ADC2） | 被静音那一路 `rms → 0`，另一路不变 | 隔离「哪一路真的有麦」「L/R 是否对调」 |
| 确认模拟麦模式 | `0x6D` bit7/6 `DMIC_MIC1P/N_ON` 应为 0；`0x64` `EN_MOD1/2`、`EN_PGA1/2` 应为 1 | 两路 ADC 都上电、没误切数字麦 | 排除「第二路压根没上电」 |
| ⚠ **别用错** | `0x20` bit4 `ADC_SP_LRP` / `0x0C` bit5 `MST_SP_LRP` | 改的是 **LRCK 帧极性 / L-R 槽解释**，不是数据符号 | 想修「反相」而改它，只会把 L/R 交换，问题不变且更难查 |

### 2.6 AFE / BSS / GSC 的前置知识

- `mic_fe_layout()`：MONO/GSC → `"M"`，BSS → `"MM"`；`mic_fe_out_channels()`：1 / 2。`audio_manager` 在 `xiaozhi_service.c:686-689` 用这两个值设 rec 声道与 `mic_layout`，**顺序必须是 `mic_fe_init()` 在 `audio_manager_init()` 之前**。
- `afe.algo_mask` 里的 `AV_PROCESSOR_AFE_FLAG_NS_ENABLE` 实际接到 `afe_cfg->se_init`（`audio_processor.c:1212`）= **BSS 盲源分离**，不是 NSNet 降噪；AEC 必须关（本板没有播放参考通道，§53）。
- 真波束成形是独立模块 `esp_gsc_*`（`esp_gsc.h`），不在 AFE 里：帧长固定 **128 点 / 8 ms**、输入 planar、坐标 x 左→右 / y 近→远（`mic_frontend.c:578-588`），`spacing` 必须实量、`phi=90°` 为正前方；GSC 另占 PSRAM（`s_ilv/s_planar/s_fifo`）与一个 `gsc_handle_t`。
- 两个模式都要**真两路独立信号**；在 P4 之前开 BSS/GSC 属于拿未验证假设当配置。

### 2.7 不可碰的采样率契约（§73.27 / §29）

`XZ_PLAY_RATE=16000 / 2ch` 是静态锚点；网关 TTS 是 **24 kHz WAV**，ASP 的 `RESAMPLE_EN` 做 24k→16k、`CH_CVT_EN` 做 1→2ch。慢放铁律：**数据格式 ≠ 流声明格式 ⇔ 2/6 倍慢放**。所以双麦调试期间：

- **不要**关 `CONFIG_ESP_AUDIO_SIMPLE_PLAYER_RESAMPLE_EN`，不要改 `RESAMPLE_DEST_RATE` / `CH_CVT_*`（`sdkconfig` 里四项已固定，§29）。
- 不要改播放链路、不要再动 `managed_components/`（组件已是官方原版，`.gitignore:7` 忽略该目录）。
- BSS 把上行从 1ch 变 2ch 时，**只改 rec 侧**，play 侧 16k/2ch 保持不动。

#### P4.4 组合判定（四条全过才判「双麦成立」）

```
P4.1 corr ≡ +1.000 且两路 RMS 相等   -> 统计与槽位映射可信（工具可信）
  + P4.3 两路可各自独立静音          -> 输出通路独立、槽位无对调
  + P4.2 与 P2 软件翻转同结果        -> 反相确实在 codec 通路，不是软件/槽位假象
  + P3   sel=6 时 MIC2P 有信号       -> 第二只麦物理存在
  ==> 双麦成立，可进 P5
```

#### 实现要点（改这块的人必须知道）

1. **幂等**：`p4_write_bits()` 先读，只有目标位不同才写；写完读回校验。日志只在"真的改了"时打一行 —— 否则每 5 s 一次补写会把 `diag` 行淹掉。
2. **会被别的模块冲掉**：`audio_service.c` / `rec_local_service.c` 重开 mic 会把 `0x20/0x23/0x25` 写回默认 ⇒ attach 写一次 + `mic_fe_dump_stats()` 每 5 s 补写一次（四项全关时 `p4_apply_probes()` 是空函数，连 I2C 都不碰）。
3. **可清位（§32 改）**：`p4_write_bits()` 做 `(v & ~bits) | (value & bits)`，设位和清位一次算完
   ⇒ 运行时切回 `all-off` 会**真的把寄存器复位**，同一次上电内可反复 A/B。
   `s_p4_touched` 门闩保证：全关且从未改过时 `p4_apply_probes()` 直接 return，连 I2C 都不碰。
4. **绝不能碰 `0x23` bit5**（ADC1←ADC2），那会把 L 覆盖掉；`0x25` 的低 5 位是 HPF coef2，必须原样保留（RMW 天然满足）。
5. 正常固件标志行：`MIC_FE: build cfg P4: copy21=0 hwRinv=0 muteADC1=0 muteADC2=0 (all off)`。
   **若行尾还有 ` runtime=ON(long-press SET)`**，说明这是调试固件（长按 SET 会改寄存器），不能交付。
6. 静态校验：`esp-idf-syntax-check` 真实编译（`-c -o NUL`）跑了 **6 种编译期组合 + 4 种运行时常量组合**全绿；
   `kconfiglib` 单独解析 `Kconfig.projbuild`，5 个新符号 `default=n`、0 warning。

**回退**：
1. 运行时态：长按 SET 直到 `P4 runtime -> [0/4] all-off`；
2. 交付配置：四项编译期开关全取消 + `CONFIG_MIC_FE_PROBE_RUNTIME_SWITCH` 也改回 n →
   `idf.py reconfigure` → `build`（改过 Kconfig 必须 reconfigure，否则 `build/config/sdkconfig.h` 还是旧的）。

## 6. 未闭环与本轮边界

- **P4 已实现并上机验证**（2026-11-11）：`main/Kconfig.projbuild` 四个开关 + `mic_frontend.c` 的
  `p4_apply_probes()`/`p4_dump_regs()`；五态实测全过（`改动记录.md` §33）。
- **双麦已落地为 BSS**（2026-11-11，`改动记录.md` §34）：`MIC_FE_MODE_SEL_BSS=y` / `INVERT_R=y`，
  带"AFE 创建失败 ⇒ 单麦降级"兜底。**尚未上机**，BSS 的实际分离效果（识别率 / CPU / 内存）待实测。
- `task_wdt / fa_resample_process`（§29）根因仍未定位，上行 AFE 的 `aud_rate_cvt` 是下一步嫌疑；与双麦调试解耦。
- ES8389 datasheet 未定义 `INPUT1/INPUT2` 引脚映射与差分极性 ⇒ 这两个问题**只能靠 P4 对照实验钉死**，不要再试图从枚举名/ES8390 注释推断（已用实测钉死：右路反相）。
- 官方原理图的麦克风本体与偏置页尚未取到；**麦间距未知**，所以 GSC 不具备启用条件。
- `0x20 / 0x23 / 0x25` 这些位 `esp_codec_dev` 没有封装 API，只能自己 `read_reg` + `write_reg` 做 RMW；幂等补写已经落在 `p4_apply_probes()` 里（见 P4 实现要点 2）。
