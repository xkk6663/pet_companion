```

├── config.json            # 网关配置（chmod 600，含 abk 密钥）
```

**消息流（一个文字回合）：**



```
设备 ──ws text──▶ 网关 ──POST /api/v1/chat(SSE)──▶ AstrBot
设备 ◀──ws text── 网关 ◀──拼接 plain 增量── AstrBot
设备 ◀──ws emotion:speaking── 网关
设备 ◀──ws audio:/static/tts_*.wav── 网关 ◀──百炼 SpeechSynthesizer── 生成并落盘
设备 ◀──ws emotion:idle── 网关
```

**语音回合（PTT）多一步：** 设备上行 `pcm(base64)` → 网关封 WAV → SenseVoice 转写 → 文字进 AstrBot（流程同上）。

## 6. AstrBot Open API 对接细节（实测确认的硬约束）



| 约束                    | 说明                                                                                            |
| --------------------- | --------------------------------------------------------------------------------------------- |
| 认证                    | `Authorization: Bearer abk_...`（chat scope）。密钥现用 `mao-pet`（2026-10-22 建，scopes: chat/im/file） |
| 地址                    | `POST http://127.0.0.1:6185/api/v1/chat`（容器内可达，勿走公网）                                          |
| **enable\_streaming** | **必须传 JSON true**（字符串 `"true"` 会被拒，AstrBot 侧校验类型）                                             |
| 会话                    | `session_id` 独立（`xz-s31-*`），与微信会话隔离（D6）                                                       |
| SSE 帧                 | `session_id` → `user_message_saved` → `run_started` → `heartbeat`（无文本）→ `plain` 增量            |
| 收尾                    | **没有&#x20;**`complete`**&#x20;帧**—— 以流关闭为准，拼接所有 `plain.data`                                  |
| 错误                    | `{"type":"error","data":...}` 帧 → 网关抛错下行 error                                                |
| 文本清洗                  | 回复可能带 `⟦MODE:chat⟧` 模式标记与重复段落；网关 `clean_reply_text()` 取最后一段（已实测生效）                            |

> 注意：回复里出现 "用户重复问同一句" 之类的重复内容，是 AstrBot persona / 双输出机制产生的原文，非网关 bug。如需更干净，可在 AstrBot 侧调整 persona（用户既有 "大肥鱼" 人设定稿，不建议网关侧强改）。

## 7. TTS 对接细节（百炼 SpeechSynthesizer）



* 端点：`https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer`

* 请求：`{"model":"qwen-audio-3.1-tts-flash","input":{"text":...,"voice":...,"format":"wav","sample_rate":24000,"instruction":...}}`

* 响应：`output.audio` 两种形态，**都必须支持**（AstrBot 原实现已实测两态并存）：


  * `data`（base64）→ 直接解码；为空时回退 ↓

  * `url` → HTTP 下载

* 流式 WAV 规整：响应 WAV 可能带长度占位与 `FF FF` 流式标记（播放器会读成 4 万秒），必须走 `normalize_wav()` 重写（已照抄 AstrBot 同款，实测音频 1.79MB 有效）

* 失败降级：TTS 异常 → 下行 `error:tts_failed`，文字气泡不受影响（P4 原则）

* 落盘：`/opt/pet_gateway/static/tts_{uuid12}.wav`，经 `http://<ip>:8081/static/...` 可达



***

## 8. ASR 对接细节（OpenAI 兼容转写）



* 端点：`{api_base}/audio/transcriptions`（`api_base` 从 AstrBot 配置自动读取）

* 请求：multipart `file`(wav) + `model`（SenseVoiceSmall）

* 设备上行 `pcm`：base64 解码 → **裸 PCM 需封 WAV 头**（16k/mono/s16，`pcm16_to_wav()`）→ 上传

* 上限：`max_pcm_seconds=10`，超长截断（架构 R8）

* 失败降级：ASR 异常 / 空转写 → `error:asr_failed`（"没听清，请再说一遍"）

* 备选：若想换百炼 `qwen3-asr-flash`，改 `PROVIDERS["stt"]` 来源或在 config 增加 asr\_override 即可（P7 再议）

## 10. 插件开发指南（云端 AstrBot 插件）

### 10.1 定时 / 事件主动推送（桌宠灵魂）

AstrBot 插件（如 proactive\_chat 已有插件）在事件触发时：



```
import requests

              json={"session_id": "xz-s31-xxxx",
                    "text": "该睡觉了，明天还要早起",
                    "emotion": "sleepy", "tts": True},
              timeout=10)
```

### 10.2 反向调用设备工具（action relay，v0.5.0 已落地）

⚠️ **原方案作废**：本节早先写的是"AstrBot 插件直接 `requests.post("http://<设备IP>/api/punch")`"。
设备在 NAT 后面（实测 `192.168.10.111`），**云端根本不可达**，这条路物理上不通。

现在统一走**已常连的 WS 反向 relay**（协议与设备端实现见
`改动记录.md` §11 / `11_遇到的问题.md` F54）：

```
网关 --{"type":"action","id":N,"name":"punch","args":{}}--> 设备
网关 <--{"type":"event","event":"action_result","id":N,"ok":1,"data":"…"}-- 设备
```

**动作名**：`punch` / `capture` / `music`(`args.name`) / `wallpaper`。
超时 45 s（打卡含摄像头启动 + 人脸识别，实测 < 35 s）。

三种用法：

1. **关键词快速路（默认，已生效）**：网关自己识别"打卡/拍照/点歌/换壁纸/自拍"，
   直接下发 action，**不进 LLM、不花 token**，延迟 = 一次 TTS。
2. **AstrBot 插件做 function-calling**（未来）：插件打网关而不是打设备：
   ```python
   r = requests.post("http://127.0.0.1:8081/action",
                     json={"session_id": "xz-s31-fc50", "name": "punch"},
                     timeout=60)
   # -> {"ok": true, "data": "「张三」打卡成功，照片已存"}
   ```
3. 调试：`curl -X POST localhost:8081/action -H 'Content-Type: application/json' \
   -d '{"session_id":"xz-s31-fc50","name":"capture"}'`

**为什么网关要并发收包**：一条 text 回合里网关要 `await` 设备回执；如果 WS 收包循环
是串行 `await handle_message(...)`，回执永远读不到 ⇒ 每个动作都超时。所以
`ws_endpoint` 改成 `asyncio.create_task()`。

设备端 HTTP 端点（`/api/punch` 等）仍然保留，用于**局域网/网页**直连调试。
