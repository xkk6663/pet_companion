## C. 快速路（0 token，不进 LLM）

> 这类话术由网关 `match_intent` 用 caps 里的 `aliases` 直接命中，**不消耗 token、几乎零延迟**。

- [ ] **C1 打卡** —— 说「帮我打个卡」
      串口：`AI_ACT: accept 'punch' id=N args={}`
      之后：`AI_ACT: result punch id=N ok=1 -> 「xxx」打卡成功，照片已存`
      `AI_ACT: stack left xxxx B after 'punch'`　←　**若 < 1500 告诉我，我再抬栈**
      网关侧**不应**出现 AstrBot 工具调用记录
- [ ] **C2 绝对音量** —— 说「音量调到80」

- [ ] **C3 相对音量** —— 说「声音大一点」
      走 LLM：`pet_speaker_get_volume` → `pet_volume {"value":75}`
      音箱比 80 再大 15
- [ ] **C4 点 chip** —— 点底部「打卡」chip，行为与 C1 一致

## F. 音频：TTS / 点歌 / 双通道续播 / 落盘（本轮重点）

- [ ] **F1** 会话建立时 `I (xxxx) PET_SVC: music channel ready (priority 1 < 2)`
      ↳ 若出现 `music channel open failed -> fallback to shared handle` ⇒ 双通道没开成，
        **告诉我**（说明内部 RAM 不够），此时 TTS 仍会顶掉音乐，但说话/点歌不受影响
- [ ] **F2 点歌** —— 说「放一首晴天」
      串口：`AI_MUSIC: play cloud: 晴天 (http://.../v1/download?id=...)`
      回话：「开播了。」（这是设备**真判**出来的结论，不是受理即报）
      **真的出声**
- [ ] **F3 暂停（关键）** —— 歌在放的时候，对她说一句话
      串口必须依次出现：
      ```
      AUDIO_PROCESSOR: Policy paused player, priority:1 < 2
      PET_SVC: play music PAUSED (ducked by tts)
      PET_SVC: play tts PLAYING
      ```
      ↳ 是 **PAUSED 不是 STOPPED**，这是本轮的判据核心
- [ ] **F4 续播（关键）** —— 她说完之后
      ```
      PET_SVC: play tts FINISHED
      AUDIO_PROCESSOR: Policy resumed player, priority:1
      ```
      **音乐从原位置接上继续放**（不是从头、不是没声）
- [ ] **F5 落盘** —— 点歌后约 3~10 s
      `AI_MUSIC: cached -> /sdcard/music/周杰伦-晴天.mp3 (x.x MB)`
      ↳ 失败只出 `AI_MUSIC: cache skipped: xxx`，**歌照放**，属正常降级
- [ ] **F6 二次点同歌** —— 再说一次「放晴天」
      `AI_MUSIC: play local: /sdcard/music/周杰伦-晴天.mp3`　**秒起**
- [ ] **F7 停** —— 说「停」，只停音乐，不砍正在说的 TTS
- [ ] **F8 按键打断** —— 按住 PTT 说话，TTS 和音乐**两路都停**

**F 段全过 = "TTS 顶掉音乐且不续播" 这个老问题真的解决了。**

## H. 已知行为 —— 别当 bug 报

这些是**已知且有意保留**的，测到不用告诉我：

| 现象 | 原因 |
|---|---|
| 图卡 8 s 后消失 | 有意设的 TTL，避免占屏 |
| 停在相机/文件页时收到的图看不见 | 图只在桌宠页渲染（下载照常，只是渲染在别的页） |
| 图片下载失败屏幕没反应 | 只打串口日志，`last_error` 接口还没有消费者 |
| 表情包首次可能等 1~2 分钟 | LLM 慢 + SSE 拉全长；网关超时已提到 150 s，但没有"先安慰一句" |
| 音乐被暂停的那几秒听不到 | policy 是"让位"不是"压低音量"（不是 ducking） |
| resume 后偶尔没声但状态是 PLAYING | 若服务端已掐流会这样；**真遇到请告诉我**，我补"resume 后无进展判死" |
| 听歌时她不说话只打字 | 点歌后 10 s 内网关压掉 TTS（`MUSIC_TTS_GUARD_S=10`），防刚起播就被暂停 |
